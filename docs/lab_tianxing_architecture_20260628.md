- 2026-06-29 必须补完整开发计划报告，报告审过后再决定是否接入生产调度。

## 玩法模型

- 定命是一切前提：没有定命，推命/改命不知道服务哪条路线。
- 推命用于积累天机值：命中给天机值，用来保障后续改命。
- 改命是最终目标：应优先服务即将发生的路线动作，尤其是探索类动作。
- 探索类动作理论日量：12 次野外历练 + 2 次探寻裂缝 = 14 次。
- 最坏天机需求：每次改命 3 点，`14 * 3 = 42` 天机值。
- 实际消耗会下降：推命命中会返天机；改命可能以“待发”形式跨越一次成功探索，不一定每次都消耗。

## 目标接口草案

```python
build_tianxing_route_preflight_plan(
    route,
    reason="野外历练|探寻裂缝|闭关|斗法",
    deadline_at=next_action_deadline,
    now=now,
)
```

返回字段：

- `route_allowed`: 下游路线动作是否可继续。
- `stage`: `need_panel`、`need_observe`、`need_set_star`、`need_change_fate`、`need_predict`、`ready_*` 等阶段。
- `prepare_command`: 需要先发送的天星命令，lab 阶段只展示不执行。
- `reason`: 给审计/UI 展示的原因。
- `lab_only`: 当前必须为 `True`。
