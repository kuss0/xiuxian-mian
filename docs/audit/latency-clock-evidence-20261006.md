# 延迟报表时钟证据

## 范围

仅调整 `tools/module_latency_report.py` 的离线只读报告。不导入运行态模块，不调用 Telegram/MiniApp，不读写业务数据库，不改发送、回包、恢复、冷却或等待线。CLI 合入后可直接使用，无需重启服务。

原有 `first_reply` / `final_event` 与 slow samples 仍采用本地日志观察时间；额外提供服务器首回包、最后一个已观察事件的服务器延迟，以及服务器最早事件的入日志滞后。最后事件不等于已验证的业务终局，报告不代替 reducer。

## 证据边界

- 只有同群、同消息 ID、同非空整数发送身份、相同非空命令正文的非转发 message echo 才提供命令服务器时间；负数频道身份保留支持。不能用用户名、空身份相等或其他群相同 ID 认领。
- 服务器时间缺失、非数字、布尔、非有限、超大整数、未来、回包早于命令或命令时钟冲突时，不产生服务器样本；仍保留原观察统计。任一回包缺少可信时钟时不宣称完整服务器终态延迟。
- 重复 echo 不增加样本；乱序入日志分别按服务器时间与观察时间处理。最早服务器事件重复观察时取其最早本地观察。
- 继续沿用原直接回复筛选及 Bot 标记规则，不扩展为官方 Bot 身份鉴权或跨祖先回包绑定；不把本报告用作恢复/补发的授权证据。历史缺失字段不猜测迁移。
- 双时钟均只有本地窗口已收集到的事件，不证明 Telegram 历史完整。未匹配数量是报告覆盖缺口，不是业务失败数量。
