## 使用

网页「副本」弹窗新增「出海猎妖、玄骨遗府与长风试炼」。新功能默认关闭且没有预置队伍。

- 猎妖：配置并保存后，在管理员日志群发送 `.猎妖 出发 队伍名`；用 `.猎妖 状态`、`.猎妖 停止 队伍名` 查看或停止；未揭示海况需人工决定，不猜测动作。
- 玄骨：先配置副群、集结群和允许参与的身份；在集结群发送 `.开启玄骨 @队长 @队员1 @队员2 @队员3 @队员4`；队长所属本机负责开启。默认收尾为「收拢遗宝」，可以配置。解散指令只接受本机监听账号发起。
- 长风：默认每日上限一场，可选麦田/竹林。日志群支持 `.长风试炼 执行 @身份 麦田`、`.长风试炼 状态`、`.长风试炼 核对 @身份 麦田`。核对只调用 status，不重放动作、不清除 held 记录。
- 长风人工恢复：先在游戏中确认旧局结束，再按状态中的准确记录号发送 `.长风试炼 确认结束 @身份 <记录号>`。只接受 held 记录；保留原回执、保守计入一次消耗，次日再安排。
- 储物袋：默认「自动路由」保持原有故障切换策略。显式主群/副群不自动转到其他群；排队期间群或话题变更会停止该任务，须重新预览。

## 保守差异与验收范围

- 所有游戏命令经过本地 `send_game_command` 和 `operation_check`；没有移植上游的节流绕过，也没有重写共享发送队列。
- 玄骨每条变更命令在发送前持久化尝试。发送结果未知时不自动重复加入、进入、行动或收尾；分工与满员需真实面板确认，发送成功本身不代表业务成功。
- 重启后猎妖/玄骨标记中断，长风标记待核对，均不恢复旧动作。
- 长风保留 `carryAvailable=0`；以开局 `rewarded` 判断是否消费有奖次数；pending 等待完整 `retryAfter`，原 wave 与 report 保持不变；传输异常不重试变更请求。
- 长风没有移植固定甲上战报，改用 55–74 的随机保守指标。提交前对最终序列化 report 重算来源文档中的评分公式；这里是指标协议校验，不是浏览器战斗物理回放。未进行真实游戏提交，不宣称实际掉落、评定或游戏风控已验收。
- 长风首次评定不符或异常即停止，保存本次 report 与实际回执，保留已消费次数；不继续尝试相邻目标。
- HTTP 配置接口使用现有会话鉴权及 POST 校验；没有新增匿名配置通路。
- 该次交付只完成代码、离线/模拟协议和服务部署验收；真实猎妖、玄骨结算与长风奖励须在用户启用后按真实回执验收。
