## Renderer ownership and scope

`tools/qingxi_native_warmup.js` adapts the official cached `dwelling-3d.js` `guardCompileAsync` poll: missing/disposed programs no longer strand the asynchronous wait, and a continuously unready program stops waiting on the first poll strictly past ten seconds. Synchronous `renderer.compile` throws remain synchronous. Native `prepareEffects` retains its original warning/soft-failure behavior; the candidate never assigns model readiness, loading state, HP, clocks, movement or coordinates.

The source basis is `dwelling-3d.js` SHA256 `279e69decbcb430f968a4400256e41fc0995c9e49e06dad1a9b26b6ce6876656`, guard lines 27–42. The affected Three r160 method is from `three-0.160.1.min.js` SHA256 `170c6789f43217c96b3170f4b42fafe135de7f7cd48497a4218f9757ee1d49fa`. Capture requires exact function text equality, so a changed engine or an existing native guard remains untouched. A missing or unrecognized shape produces a fixed unsupported counter and retains native behavior.

The main controller's three one-off unauthenticated public-source reads all returned HTTP 403 (`/root/xiuxian-qingxi-7plus6-release-20261121/native-warmup-public-source-2328/metadata.json`). Current client source could not be refreshed. The local snapshot is a provenance reference, not proof of the version currently served. Real acceptance must observe `native_warmup.installed=1`, calls through that guard, and subsequent native `modelReady`/scene readiness. Unsupported methods keep native behavior and cannot count as successful candidate use.

The pinned user-script factory anchor is replaced only once, after provenance verification. The capture runs synchronously after `Reflect.apply` returns the runtime and before publication to its caller. Model fetching/parsing precedes the asynchronous warmup, so this is early enough for new work. It cannot rescue a Promise already hanging before capture. The helper is injected only for active quest workers, not read-only inspection or daily/reward workers.

Ownership is per renderer through a WeakMap and one current renderer reference. A new runtime releases the previous owned override; repeated capture/injection is idempotent. Revoke restores only a method still owned by this adapter and preserves a later official replacement. It restores inherited methods by removing the override. Existing polls keep their finite closure after revoke, so revocation cannot strand native awaits. An external actor freezing the renderer can prevent restoration; `restoreErrors` records this without aborting cleanup. `activeRenderers=0` then means no tracked owner, not proof the original descriptor was restored.

This instance also serves field-combat shader preparation. The change is not limited to a character's visual mesh. Real rendering, driver faults, long synchronous shader compilation and subsequent native combat warmup still require acceptance by the main controller. No Three prototype, motion authority or reduced-motion preference is changed. Reduced motion was rejected because the official `updateBlink` changes movement timing at approximately 80 ms.

`SNAPSHOT.native_warmup` contains only fixed numeric counters. There are no URLs, authentication data, full runtime snapshots, exceptions or unbounded event lists. Worker cleanup calls revoke after stopping automation and before its existing drain/fresh-status verification.
