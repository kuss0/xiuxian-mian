# 试炼失败前缀持久交接

## 范围

仅修复公共入口日批次的失败步骤在暂停/异常后丢失的问题。不改试炼 HTTP、身份开关、授权、发送/回包、回执判定、每日额度、跨日未知归档或通知发送器。候选先合入磁盘，不为此重启主服务。

## 发现

`_run_cave_public_entry_batch()` 原先把失败身份留在局部 `failed_steps`，暂停时仅保存失败数量、完整步骤和已完成游标。恢复传回数量，却重新初始化空失败清单。剩余步骤成功后，结束条件只检查空清单，可能把还有失败的批次标记完成。

首轮独立回放的四个断言在原代码失败：全局暂停、共享限流、异常中断三种退出丢失失败清单；旧失败计数缺少身份依据时仍可恢复。暂停测试使用真实生产判定文案，不以任意“暂停”文字代替契约。

## 修复

- 两个 wave 各在现有 `miniapp_auto_config` 增加 `last_failed_steps`，沿用现有 JSON/SQLite meta 编解码，不新增数据库表。
- 保存、重读、UI 启动、调度保存及 worker 参数保持同一失败清单；暂停、共享限流、上游中断、连续入口失败和异常退出均保存。
- 失败清单必须与失败数量一致，且逐条属于已执行前缀；拒绝缺失、未来步骤、外来身份/动作和超额重复项。旧记录没有身份依据时保留待核查，不猜测重跑，也不标记完成。
- 正常结束仅将已知失败步骤放入下一轮，成功步骤不回放；清空新一轮的已执行失败前缀。真正完成才清除整个执行清单。
- 早退同时保留已观察到的未知结果原因，不能以暂停或上游失败抹掉原有冻结。未知请求仍使用原恢复门禁。

## 剩余边界

- 不解决成功子步骤与父批次之间的逐步耐久交接、进程强制中断后的完整恢复，也不宣称 exactly-once。
- 不解决跨失败重试的收益替换/去重、取消后收益交接或通知送达未知。现有子通知必须保留，不能因本修复直接删除。
- 部分步骤的累计收益仍须以 operation/结算回执去重，不能直接把旧汇总累加到新汇总。
- 若退回旧 worker，旧代码不会使用新增失败清单。应在无活动批次时维护；有失败前缀时不得用重启旧代码来恢复工作。
