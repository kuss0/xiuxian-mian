## 不能整体替换的原因

1. **覆盖不完整。** 使用说明第14行、每日 launcher 的目录和只读 checker 均为月殿、血色、南门、护民、神坛五每日加麦田/竹林两场地，缺试傀场与剑冢。另一个穆姓上师是支线 Boss，不补这两个每日。主线 `qingxi_quest_run.js` 的 QUESTS 只到 q61，后附游记/御风车支线，不提供我方 q64/q67 目标的完整主线推进。
2. **试炼和每日重试不兼容。** 分享版 Python 默认最高重数、retries=6；`qingxi_quest_bot.js:663` 的副本战败可重试四次。月殿启动器有重复开局与结算未知后重打一局的路径。我方固定一重、零重试、当天同场地真实首败停止和原局 held 对账不能放宽。
3. **单项选择不等于写范围。** `__dailyPick` 只过滤客户端循环，未在请求层拒绝其他副本/试炼写入；不能替代我方七 ID 白名单和 `reward_one` 的排他范围。
4. **已领奖可能掩盖退出失败。** `qingxi_daily_dungeons.js:148–159` 会附加“离场未确认”，但 `qingxi_daily_launcher.py:157–169` 的 summary 只看已领，可能仍报告成功并关闭 Chrome。没有我方独立飞行闭合、内存/磁盘 pending、同日同 run 的完整安全证明。
5. **旧缓存不能证明新场地可开。** 分享版试炼查询失败可退旧缓存，离线反例能返回昨日麦田缓存来回答今日竹林。不能接到开局或 held 放行谓词。
