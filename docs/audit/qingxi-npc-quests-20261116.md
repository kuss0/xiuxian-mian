# 青溪坊 NPC 任务接入

任务状态来自官方 `/api/miniapp/xianxia-dwelling/quests`，规则来自
`qingxi-quest-design-v1.json` 和 `dwelling-quests.js`。精简目录在
`model/features/qingxi_quest_catalog.json`，包含原始资源 SHA256。

目录覆盖官方九份资源中的 79 项任务，包含越国、九国盟、天道盟。
2026-11-16 再次读取九份官方静态资源，SHA256 均与目录来源一致。
简单对话、送信、采集、限时交付复用轻量协议；真实移动、野外战斗、
机关、剧情副本和跨区路线复用上游 PR #8 洞府助手 v2.0.53，替换临时
战斗循环。未开放或未知目标继续显示缺口；目录覆盖不等于全部实测通过。

`vendor/dwelling-autobot/trial-bot.user.js` 保留上游原文，提交固定为
`2d0c11fbaa9891a6e9a4f09751dc59bc23b56bb2`，启动前校验 SHA256。
本地策略位于 `tools/qingxi_quest_policy.js`；仅在内存适配两处明确锚点，
让未选奖励和任务钓鱼进入上游暂缓分支，继续其他任务。锚点变化拒绝启动。

- `available -> active/ready -> rewarded` 才是已确认的任务生命周期。
  服务端实际使用 `rewarded`，不能把本地发送成功当作领奖。
- 每次写请求先保存唯一 operationId。结果不明时保留 pending。
  只读状态可以确认已接取、已领奖；不生成另一条写请求。
- 同一份进度下重复动作立即停止。数量按服务端 required 覆盖目录值。
- 任务控制请求间隔至少 5 秒，合并并发状态读取。浏览器每轮最多
  15 分钟、8 项交付；同一进度按上游超时停止，失败不自动重开。
  官方施法凭证有独立批量传输与超时，保留其原生时序及独立预算，
  不排在任务查询后；每次写入前保存操作日志，未知结果立即冻结后续写入。
- 此 NPC 流程禁止每日试炼 start/report/checkpoint，禁止额外抛竿。
  剧情副本开始前按各自场地核对当天 claimed/hasKey；已领奖、未解锁、
  存在旧局则停止开局，同一轮不重开失败副本。已满奖励等到次日再查。
- 复用洞府会话、已选玩家校验、账号占用和公共入口锁。
  重启时保留未确认的采集、写请求、浏览器结算状态。
  浏览器启动前持久化待核对标记；只有身份一致、正常退出且最终状态
  已核对才释放。结果文件缺失、损坏或进程取消时保留占用，防止其他
  副本抢占未结算场景。
- 河岸任务使用 `qingxi-riverside`，不是洞府 `west-shore`。
  它复用已有钓鱼计划和日限额，不额外抛竿、不增加限额。
  钓获落账后只唤醒任务调度，由新服务端状态决定是否交付。
- 奖励选项由活动配置显式设置，默认保留待选。
- 页面显示任务开关、战斗开关、参与账号、进度和待选奖励。
  通知仅汇总已确认交付和实际资源；通知发送不明时不重复发送。

接口：`POST /api/qingxi-quests`，`status` 只读本地记录，`refresh`
读取一次游戏状态，`run` 安排一轮任务。使用现有 UI 鉴权。
`/api/expedition-config` 的 `qingxi_quests` 字段设置参与名单、
`enabled`、`gameplay_enabled` 和 `choices`。

2026-11-16 首轮吧唧实测确认：入坊登记、送信、采药、炉料四项均为
`rewarded`。第五到第七项已接取，分别需要野外击杀、拾取货包和
河岸钓鱼。吧唧当日已有 5 次钓鱼记录，任务不能绕过日限额。

后续入坊回执确认：位置保存 `/location` 在切换场景时可能返回非 JSON；
它不消费任务或试炼奖励，已从任务写请求冻结逻辑排除。社交只读查询
同样不冻结任务。历史冻结只有在证据证明没有任务、战斗写入后，才可
通过一次任务只读刷新复核解除，未确认的领奖和战斗操作继续保留。

御空 `tick/stop` 保留官方传输及清理逻辑：心跳 3 秒超时，连续三次
失败安全降落，结束失败等待会话过期。本地守卫不阻断这两种原生清理，
起飞仍受保护。历史心跳冻结只有在证据无任务/战斗写入，且新读取的
官方 `flight` 状态明确为 `mana.flightLocked=false` 时才解除。
